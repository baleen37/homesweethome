## 1. 요약

문래동(영등포구)은 ASIL API에 아파트 데이터가 존재하지 않아 분석이 불가능했습니다. 대신 여러 지역의 데이터를 분석한 결과, **이전 분석에서 언급된 필드 완전도 문제의 실제 원인은 DTO 매핑 누락**이었으며, **API 응답 자체의 누락은 아님**을 확인했습니다.

### 주요 발견

1. **DTO 누락 필드**: `building`, `type`, `etc` 필드가 `AsilAptListDTO`에 정의되어 있지 않음
2. **필드 완전도 (API 응답 기준)**:
   - `movein`, `total_dong`, `type`, `building`: 100% (모든 레코드에 존재)
   - `offer`: 4.4% ~ 35.8% (지역별 차이)
   - `etc`: 0% (모든 레코드에서 빈 문자열)

## 4. 필드별 상세 분석

### 4.1. offer 필드 (매물 정보)

**데이터 타입**: 문자열 (예: "매물 2건", "매물 22건")

**완전도**: 4.4% ~ 35.8% (지역별 차이)

**샘플 데이터**:
```
SK허브젠: "매물 2건"
강남서해더블루: "매물 2건"
강남센트럴아이파크: "매물 22건"
강남역서희스타힐스: "매물 2건"
강남역센트럴푸르지오시티: "매물 7건"
```

**분석**:
- 현재 매물이 있는 아파트만 "매물 N건" 형식으로 값이 존재
- 매물이 없는 아파트는 빈 문자열 (`""`) 반환
- 이는 API 설계상 의도된 동작으로 보임 (매물 없음 = 빈 문자열)

### 4.2. movein 필드 (건축 연도)

**데이터 타입**: 문자열 (YYYY 형식)

**완전도**: 100%

**고유값 예시**: `['0', '1974', '1978', '1979', '1980', ...]`

**분석**:
- 모든 레코드에 존재
- 일부 아파트는 '0' 값 (건축 연도 미상 또는 데이터 누락)
- DTO에서 `build_year` 필드의 `alias`로 매핑되어 있음

### 4.3. total_dong 필드 (동 수)

**데이터 타입**: 문자열

**완전도**: 100%

**고유값**: `['0', '1', '2', '3', '5', '6', '7', '8', '11', '12']`

**분석**:
- 모든 레코드에 존재
- 일부 아파트는 '0' 값 (단독 건물 또는 데이터 누락)
- DTO에서 `dong_count` 필드의 `alias`로 매핑되어 있음

### 4.4. type 필드 (건물 유형 코드)

**데이터 타입**: 문자열

**완전도**: 100%

**고유값**: `{'0'}`

**분석**:
- 모든 레코드에 존재
- 현재 테스트한 데이터에서는 모두 '0' 값
- **DTO에 정의되어 있지 않음 (매핑 누락)**

### 4.5. etc 필드 (기타 정보)

**데이터 타입**: 문자열

**완전도**: 0%

**고유값**: 모두 빈 문자열 (`""`)

**분석**:
- API 응답에는 필드가 존재하지만, 모든 레코드에서 빈 문자열
- 현재 사용되지 않는 필드로 보임
- **DTO에 정의되어 있지 않음 (매핑 누락)**

### 4.6. building 필드 (건물 유형)

**데이터 타입**: 문자열

**완전도**: 100%

**고유값**: `{'dasede', 'apt', 'officetel'}`

**분석**:
- 모든 레코드에 존재
- `apt`: 아파트, `officetel`: 오피스텔, `dasede`: 다세대/다가구
- **DTO에 정의되어 있지 않음 (매핑 누락)**

- `offer`: 32.3%
- `movein`, `total_dong`, `type`, `etc`: 0%

- `offer`: 4.4% ~ 35.8% (지역별 차이)
- `movein`, `total_dong`, `type`: 100%

**차이 원인**:
1. **DTO 매핑 누락**: `type`, `etc`, `building` 필드가 DTO에 정의되어 있지 않아 이전 분석에서 0%로 집계됨
2. **별칭(alias) 사용**: `movein` → `build_year`, `total_dong` → `dong_count`로 매핑되어 있어 직접 필드명으로 확인 시 누락으로 판단 가능

| movein | 100% 존재 | O (alias) | 0% | 매핑 확인 누락 |
| total_dong | 100% 존재 | O (alias) | 0% | 매핑 확인 누락 |
| type | 100% 존재 | X | 0% | DTO 매핑 누락 |
| etc | 100% 존재 (빈 문자열) | X | 0% | DTO 매핑 누락 + 실제 빈 값 |
| building | 100% 존재 | X | - | DTO 매핑 누락 |

## 7. 결론

1. **문래동 데이터 부재**: 영등포구 문래동 및 인근 지역은 ASIL API에 아파트 데이터가 존재하지 않음

2. **DTO 매핑 누락 확인**: `building`, `type`, `etc` 필드가 DTO에 정의되어 있지 않음

3. **필드 완전도 실제 상태**:
   - `movein`, `total_dong`, `type`, `building`: API 응답에 100% 존재
   - `offer`: 지역별 4.4% ~ 35.8% (매물이 있는 아파트만 표시)
   - `etc`: API 응답에 필드는 존재하지만 모든 레코드가 빈 문자열

4. **개선 우선순위**:
   - 1순위: DTO에 `building`, `type`, `etc` 필드 추가
   - 2순위: 필드 완전도 모니터링 테스트 추가
   - 3순위: offer 필드 데이터 활용 방안 검토
